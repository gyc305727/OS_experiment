# 实验阶段执行与恢复流程

本流程适用于本仓库所有操作系统实验。目标是保证每个实验阶段的命令可以从明确状态开始连续执行，结果来自当前机器、当前容器和当前代码的真实输出，并且在出错时能够回到上一阶段结束状态后重新验证。

## 基本推进方式

1. Codex 每次只提供一个阶段的命令，不提前推进下一阶段。
2. 用户逐行手动执行该阶段命令，并把真实执行过程和输出结果粘贴回来。
3. Codex 根据真实输出判断本阶段是否通过。
4. 如果通过，Codex 明确说明本阶段通过，并提醒用户截图整个命令行窗口。
5. 用户按阶段图号保存截图，例如实验4阶段1保存为 `4-1`。
6. 截图完成后，才进入下一阶段。

## 阶段命令要求

每个阶段的命令必须满足：

1. 从明确的目录和环境开始，例如 Windows PowerShell 的仓库根目录、容器内 `/mnt`、`/mnt/os` 或 `/mnt/user`。
2. 命令之间前后承接，不依赖隐含的当前目录。
3. 如果需要从 PowerShell 进入容器，必须写出完整入口命令。
4. 如果需要在容器内执行，必须显式写出 `cd /mnt`、`cd /mnt/os` 或 `cd /mnt/user`。
5. 只完成当前阶段目标，不夹带后续阶段修改。
6. 不伪造命令输出、截图、编译结果或运行结果。
7. 避免一次性粘贴超长 `cat <<'EOF' ... EOF` 命令。长文件应优先拆成多个较短文件、多个较短 heredoc，或按模块分阶段写入。
8. 如果必须写入较长文件，应把“写入文件”和“截图检查文件内容”分开：先写入，再用 `sed -n` 分段查看，截图只截最终文件内容，不截混乱的粘贴过程。
9. 如果长 `cat` 粘贴过程中终端显示混乱，但后续 `sed` 和构建验证证明最终文件正确，则不视为实验失败；后续过程记录中的命令应替换为更易执行、更易截图的分段版本。

## 成功时的处理

当用户贴回输出后，如果本阶段满足成功标志：

1. Codex 说明本阶段通过。
2. Codex 指出应截图的位置，并提醒截图整个命令行窗口。
3. 用户保存截图为对应图号。
4. Codex 不自动进入下一阶段，等待用户确认继续。

## 出错时的处理

当某阶段执行出错时，必须按以下顺序处理：

1. Codex 先根据用户贴回的真实输出分析错误原因。
2. Codex 不直接给继续修复命令，而是先给恢复命令。
3. 恢复命令的目标是回到上一阶段成功结束后的状态。
4. 恢复命令必须说明：
   - 恢复目标是什么。
   - 会恢复、覆盖或删除哪些当前阶段产生的内容。
   - 不会影响哪些已经完成并截图的阶段成果。
5. 恢复命令不得使用粗暴危险命令，例如 `git reset --hard`、`git clean` 或递归删除，除非用户明确授权。
6. 用户执行恢复命令并反馈结果。
7. Codex 确认已经回到上一阶段结束状态后，再提供新的当前阶段解决方案。
8. 新方案仍必须从上一阶段结束状态开始连续执行。

## 文档替换规则

如果某阶段原命令有问题，且新方案经过用户执行验证成功：

1. Codex 只替换过程记录和报告骨架中当前阶段有问题的命令。
2. 不重写整个报告。
3. 不改动已经验证通过的阶段。
4. 不提前补写未验证阶段的结果。
5. 不把未执行的推测写成已通过结论。
6. 替换完成后，用户再按对应图号截图。

## REPORT_SYNC_BLOCK 要求

每个关键阶段完成后，Codex 输出或维护的阶段记录应包含 `REPORT_SYNC_BLOCK`，至少包括：

1. 本阶段目标。
2. 实际执行命令。
3. 成功标志。
4. 需要截图的位置，并提醒截图整个命令行窗口。
5. 本阶段修改的文件。
6. 可以写进实验报告的简短素材文字。
7. 本阶段遇到的问题与处理。
8. 是否建议进入下一 checkpoint。

## 截图命名约定

截图命名按实验号和阶段号组织，例如：

- 实验4阶段0：`4-1`
- 实验4阶段1：`4-2`
- 实验4阶段2：`4-3`

如果一个阶段需要多张图，可以使用小数或后缀，例如 `4-6.1`、`4-6.2`。

截图保存后，Codex 可以根据图片内容协助重命名。重命名规则如下：

1. 保留实验号、阶段号和阶段内顺序，例如 `4-4.1`、`4-4.2`。
2. 在顺序号后增加简短英文语义后缀，便于后续插入报告和定位证据。
3. 命名格式为：`实验号-阶段号.序号-内容说明.png`。
4. 内容说明应描述截图证明的对象或动作，例如 `user-syscall-check`、`make-build`、`artifacts`。
5. 只重命名当前阶段截图，不改动其他阶段截图。
6. 重命名前应先查看图片内容，不能只根据原文件名猜测。

示例：

- `4-3.4-make-build.png`
- `4-4.6-user-syscall-check.png`
- `4-4.8-user-app-build.png`

## 与仓库其他规则的关系

本流程补充 `AGENTS.md` 中的命令执行边界、报告同步机制、报错处理规则和截图规则。若与实验说明文本发生冲突，应以当前机器、当前容器、当前代码和用户贴回的真实输出为准。
